# Abigent 产品设计规格

日期：2026-08-08  
状态：已完成方案讨论，等待书面规格确认

## 1. 产品定义

Abigent 是一款完全在本地运行的 macOS Agent 桌面管理工具。它以用户的小猫 Abigent 为半写实桌面宠物，并通过菜单栏提供稳定的任务管理入口。用户无需频繁切回 Agent IDE，即可感知任务状态、处理 Agent 的确认请求、查看结果并继续任务。

“完全在本地运行”是指 Abigent 的连接器、任务处理、历史存储和界面均在用户 Mac 上执行，Abigent 不建设中转服务。Codex 自身与 OpenAI 服务之间原本存在的网络通信不由 Abigent代理，也不属于 Abigent 的本地化承诺。

第一版只支持 Codex 桌面应用，第二版计划支持 Trae CN。系统从第一版起采用多 Agent 连接器架构，后续接入 Claude Code、Cursor 等工具时不修改核心任务与界面层。

## 2. 产品目标

第一版必须做到：

1. 自动发现 Codex 桌面应用中已有和新建的任务。
2. 在本地同步任务状态，但只在“需要用户操作”和“任务完成”时主动提醒。
3. 允许用户在 Abigent 中直接处理确认请求和输入回复。
4. 展示完成摘要、修改文件、测试结果和快捷操作。
5. 在断线、协议异常和应用重启后恢复一致状态，且不重复发送通知。
6. 以可安装的 macOS 应用交付，业务数据不经过产品自建服务器。

## 3. 非目标

第一版不包含：

- Trae CN、Claude Code、Cursor 或其他 Agent 的正式接入。
- Windows、Linux、iOS 或 Web 版本。
- 云端账户、跨设备同步、团队协作或遥测后台。
- 在 Abigent 中创建完整 IDE 或复制 Codex 的全部对话界面。
- 基于不可靠信息猜测百分比进度。
- 未经用户授权使用 macOS 辅助功能控制其他应用。

## 4. 核心体验

### 4.1 桌面宠物

桌面上显示一只可拖动、可隐藏的半写实插画猫。角色参考用户提供的小猫照片，保留其大耳朵、金色眼睛、脸部轮廓和暖灰棕毛色。角色不采用夸张 Q 版比例，毛发细节会适度简化，以保证小尺寸下的清晰度与动画性能。

状态动作：

- 空闲：趴卧、缓慢呼吸或轻摆尾巴。
- 运行中：专注看小屏幕或轻微敲击动作，不弹出通知。
- 需要操作：抬爪、耳朵朝前并显示橙色徽记，同时弹出请求卡片。
- 已完成：起身伸懒腰或短暂庆祝，显示完成卡片后恢复安静。
- 连接中断：停止工作动作，显示中性断线徽记，不暗示任务仍在执行。

第一版的 Agent 来源通过小型项圈徽记标识 Codex。第二版接入 Trae CN 时复用同一角色，仅替换徽记或辅助色。

### 4.2 菜单栏入口

菜单栏图标是始终可用的稳定入口。展开面板后显示：

- 当前需要用户处理的任务。
- 正在运行的任务。
- 最近完成和失败的任务。
- 每个任务的 Agent、项目、持续时间、状态和静音状态。
- 查看详情、继续任务、取消任务、打开 Codex 等操作。

宠物可以隐藏，菜单栏入口不能因此消失。用户可设置开机启动、宠物是否置顶、默认显示器和通知声音。

### 4.3 需要用户操作

当 Codex 请求授权、确认或补充信息时，Abigent 显示请求原文与来源任务。用户可以：

- 选择 Codex 提供的快捷选项，例如允许或拒绝。
- 在短输入框中直接回复开放式问题。
- 展开菜单栏面板输入较长内容。
- 使用“在 Codex 中打开”回到原任务。

发送前必须显示目标任务和实际回复内容。涉及执行权限的请求不得由 Abigent 自动批准。

### 4.4 完成结果

完成卡片优先显示：

- 一句话结果摘要。
- 修改文件数量与关键文件列表。
- 测试是否执行、通过与失败数量。
- Codex 最终回复的可展开详情。
- 查看详情、继续任务、打开 Codex 和关闭提醒。

若连接器没有提供某类结果，界面明确显示“未提供”或“未运行”，不得推断测试通过或代码修改成功。

## 5. 系统架构

Abigent 使用原生 Swift、SwiftUI 与 AppKit 构建。

### 5.1 展示层

- `PetWindow`：AppKit 透明无边框悬浮窗口，负责窗口层级、拖拽、多显示器、点击穿透和角色动画承载。
- `MenuBarPanel`：SwiftUI 菜单栏面板，负责任务列表、筛选、详情和控制操作。
- `PromptCard`：需要操作时的原地确认和回复界面。
- `ResultCard`：任务完成后的摘要与快捷操作。

展示层只依赖统一任务模型，不读取 Codex 私有数据，也不直接调用 Codex 协议。

### 5.2 Task Core

`TaskCore` 是 Agent 无关的本地任务核心，职责包括：

- 将连接器事件归一化为统一任务状态。
- 保存任务快照、结果摘要和通知去重信息。
- 将用户命令路由给正确的连接器。
- 决定宠物状态与通知时机。
- 在应用重启和连接恢复后执行状态对账。

核心模型：

```text
AgentTask
  id: GlobalTaskID
  source: AgentKind
  sourceTaskID: String
  projectName: String?
  title: String
  state: TaskState
  attentionRequest: AttentionRequest?
  result: TaskResult?
  startedAt: Date?
  updatedAt: Date
  completedAt: Date?
  muted: Bool
```

统一状态包括：`discovered`、`working`、`needsInput`、`completed`、`failed`、`cancelled`、`connectionUnknown`。第一版不展示虚构的百分比；只有来源明确提供可验证进度时才显示阶段或比例。

### 5.3 Agent Connector

所有 Agent 通过相同接口接入：

```text
AgentConnector
  connect()
  disconnect()
  initialSnapshot() -> [AgentTask]
  events() -> AsyncSequence<AgentEvent>
  respond(taskID, response)
  cancel(taskID)
  continueTask(taskID, prompt)
  openInSource(taskID)
```

连接器负责来源协议和统一模型之间的转换，不负责 UI、通知和数据库。

### 5.4 CodexConnector

第一版优先连接本机 Codex App Server。实现顺序为：

1. 验证能否读取 Codex 桌面应用的已有任务快照。
2. 验证能否订阅新增任务和状态事件。
3. 验证能否读取确认请求与最终结果。
4. 验证能否对等待中的任务回复、继续和取消。
5. 验证能否深链或可靠地打开对应 Codex 任务。

Codex App Server 当前属于实验性本地协议。协议结构、消息映射和版本兼容全部封装在 `CodexConnector` 内。应用启动时检查 CLI 与 App Server 版本，未知版本进入兼容性提示状态，不让协议异常扩散到 Task Core。

若公开本地协议无法完成某个已确认能力，只对该能力设计 macOS 辅助功能降级。降级默认关闭，首次启用时解释用途并请求系统授权；核心状态读取不得仅依赖屏幕像素识别。

### 5.5 TraeCNConnector

第二版新增 `TraeCNConnector`，复用 `AgentConnector` 接口与 Task Core。具体连接方式在第二版开始前重新调研 Trae CN 当时提供的公开接口、插件机制和本地状态能力，不在第一版预埋未经验证的私有协议。

## 6. 数据流

正常任务流：

1. `CodexConnector` 连接本地 App Server 并获取任务快照。
2. Task Core 以 `source + sourceTaskID` 生成稳定的全局任务标识并写入本地数据库。
3. 后续事件按版本或更新时间合并，旧事件不得覆盖新状态。
4. 状态变化驱动菜单栏列表和宠物动作。
5. 仅当状态首次进入 `needsInput` 或终态时，Notification Coordinator 判断是否发送通知。
6. 用户回复时，Task Core 记录待发送命令并交给连接器；收到来源确认后更新本地状态。

恢复流：

1. 连接中断后，活动任务进入 `connectionUnknown`，保留最后确认状态。
2. 使用有上限的指数退避自动重连。
3. 重连后获取完整快照，与本地任务对账。
4. 使用任务 ID、状态版本和通知记录去重。
5. 无法恢复时持续显示连接异常，并提供重试和打开 Codex。

## 7. 本地存储与隐私

- SQLite 保存任务索引、状态快照、结果摘要和通知去重记录。
- UserDefaults 保存窗口位置、显示偏好、开机启动和通知设置。
- Keychain 仅在未来协议确实需要本地凭据时使用；第一版不得复制或导出 Codex 登录凭据。
- 不建设产品业务服务器，不上传 Prompt、回复、代码路径、结果或行为数据。
- 日志默认仅保存在本地，并对可能包含 Prompt、文件内容或令牌的字段进行删除或脱敏。
- 设置中提供“清除全部本地历史”。卸载说明明确指出本地数据目录的位置和删除方式。

## 8. macOS 权限与分发

第一版通过签名和公证的 `.dmg` 分发，用户拖入 Applications 安装。应用按需请求：

- 通知权限：用于需要操作和完成提醒。
- 开机启动：用户主动开启后注册 Login Item。
- 辅助功能权限：仅在 App Server 无法完成且用户选择启用降级能力时请求。

应用不默认请求全磁盘访问。若读取 Codex 本地 Socket 或数据受到沙盒限制，优先使用官方本地协议允许的连接方式，并在技术验证阶段决定签名与 Sandbox 配置。

## 9. 错误处理

- Codex 未安装：展示安装/打开 Codex 的说明，不循环报错。
- App Server 不可用：提供重连、诊断摘要和打开 Codex。
- 协议版本不兼容：禁用有风险的写操作，仍尽量保留可验证的只读状态。
- 回复发送失败：保留用户输入，明确标记未发送并允许重试。
- 任务消失：先标记来源不可见，不自动判断为完成或删除历史。
- 数据库损坏：备份损坏文件，建立新库，并向用户说明本地历史恢复情况。
- 通知权限关闭：菜单栏和宠物仍正常工作，设置中提示如何恢复权限。

## 10. 测试与验收

### 10.1 技术验证门槛

在正式界面开发前完成 Codex 连接验证。以下四项均需产出可重复的验证记录：已有任务发现、实时状态事件、最终结果读取、等待任务回复。任何失败项必须在进入完整实现前明确降级设计和体验限制。

### 10.2 自动化测试

- Task Core：状态转换、乱序事件、重复事件、重连对账和通知去重单元测试。
- Connector contract：对快照、事件、回复、取消和来源跳转运行统一契约测试。
- CodexConnector：使用录制并脱敏的协议 fixture 测试版本映射和错误消息。
- 数据库：迁移、清除历史和损坏恢复测试。
- UI：关键卡片的 SwiftUI 快照测试和基础可访问性测试。

### 10.3 手动验收

- Codex 已打开、未打开、运行多个任务和应用重启场景。
- 单显示器、多显示器、全屏应用、睡眠唤醒和菜单栏自动隐藏。
- 通知允许与拒绝、辅助功能允许与拒绝。
- 离线、App Server 重启、Codex 升级和 Abigent 升级。
- 原地允许、拒绝、短回复、长回复和发送失败重试。
- `.dmg` 安装、首次启动、升级覆盖和完整卸载。

## 11. MVP 交付物

- 原生 macOS 应用与 Xcode 工程。
- Codex App Server 可行性验证记录。
- CodexConnector、Task Core、本地存储与通知实现。
- 半写实 Abigent 角色基础素材及空闲、运行、需要操作、完成、断线状态动画。
- 签名、公证和 `.dmg` 打包流程；若开发阶段没有分发证书，则提供可本地安装的开发构建和签名操作说明。
- 用户安装与权限说明。
- 产品实现总结：逐项说明能力、模块、数据流、异常处理、测试、打包方式、已知限制和 Trae CN 扩展方案。

## 12. 成功标准

在支持的 Codex 版本上，用户可以离开 Codex 窗口持续工作，并可靠地完成以下闭环：Abigent 自动发现任务；安静展示运行状态；在需要操作时提醒并原地回复；在完成时展示可信结果；用户可以继续任务或回到准确的来源位置。整个闭环不依赖 Abigent 自建云服务，连接异常不会产生虚假状态或重复提醒。

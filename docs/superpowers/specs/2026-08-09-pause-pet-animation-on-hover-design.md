# Abigent 悬停静止与简化缩放入口设计

日期：2026-08-09

## 目标

用户将鼠标移到小猫或已展开的任务摘要卡上时，小猫本体保持静止，避免阅读和操作期间持续呼吸、摆动或弹跳。鼠标离开完整交互区域后，小猫恢复当前任务状态对应的轻微动画。

同时移除一直显示在小猫右下角的拖拽缩放按钮。小猫大小统一通过双指按下/右键操作框中的滑块调节，保持桌面形态简洁。

小猫在桌面上的位置只能通过明确的鼠标按下并拖动来改变。单纯悬停、移动指针、双指滚动或摘要卡展开不得移动小猫。

## 方案选择

考虑过三种方式：

1. **暂停完整交互区域内的小猫本体动画（采用）**：阅读稳定，同时保留进度圈、完成标识等状态反馈。
2. 完全删除所有小猫循环动画：最稳定，但会削弱桌面宠物的生命感和远距离状态感知。
3. 只在小猫图片上暂停：实现最小，但鼠标移入摘要卡后动画会重新开始，无法解决阅读干扰。

缩放入口考虑过三种方式：

1. **只保留操作框滑块（采用）**：默认界面最干净，缩放入口仍然明确可用。
2. 缩放按钮只在悬停时出现：可发现性较好，但悬停阅读时仍增加视觉干扰。
3. 保留常驻按钮：操作最快，但用户已确认没有必要且影响美观。

窗口移动考虑过三种方式：

1. **关闭背景自动拖动并提供明确的按下拖动（采用）**：输入边界清晰，普通悬停不会被触摸板误判成窗口移动。
2. 只取消摘要卡展开动画：改动较小，但不能排除背景自动拖动导致的跟随。
3. 将摘要卡拆为第二个窗口：隔离最彻底，但增加窗口同步和多屏边界复杂度，当前没有必要。

## 交互规则

- 鼠标进入小猫或摘要卡所在的完整 `HStack` 区域后，记录悬停状态并暂停小猫本体动画。
- 鼠标离开完整区域后恢复动画。
- 悬停卡片仍按现有 180 ms 延迟出现、250 ms 延迟隐藏，避免破坏已经确认的摘要交互。
- 进度圈和状态徽标不暂停，用户仍能判断 Codex 是否正在工作。
- 开启 macOS“减少动态效果”时，继续保持全部小猫本体动画关闭。
- 小猫右下角不再显示拖拽缩放按钮。
- 双指按下/右键操作框继续提供 50%–150% 大小滑块，并继续保存用户选择。
- 普通悬停只控制摘要卡可见性，不改变小猫的桌面锚点。
- 只有在小猫区域按下主鼠标键并拖动时，窗口才跟随指针；松开后保存新位置。
- 摘要卡显示和隐藏引起的窗口尺寸变化不播放窗口动画，避免插值过程中小猫视觉位移。

## 实现边界

- 在 `PetView` 内新增单一悬停状态，不改变任务模型、窗口控制器或持久化数据。
- 小猫的缩放、旋转、垂直位移函数在悬停时返回静止值。
- 避免为暂停动作添加额外过渡动画，确保鼠标进入后立即稳定。
- 从 `PetView` 移除 `PetResizeHandle`，但保留控制面板向窗口控制器传递大小变化的现有链路。
- `PetWindowController` 关闭 `isMovableByWindowBackground`，由 Hosting View 将明确的主键按下事件交给 `NSWindow.performDrag(with:)`。
- 摘要卡可见性变化使用非动画窗口调整；窗口右边缘继续作为小猫锚点。

## 验证

- 静态检查：空闲、工作中、需要操作、已完成状态的悬停值均为静止值。
- 生产构建：Release 构建成功。
- 实机检查：鼠标进入后摘要卡正常出现，小猫停止运动，进度圈仍旋转；鼠标离开后恢复动画。
- 实机检查：小猫右下角不再出现缩放按钮，操作框滑块仍可改变大小。
- 实机检查：只移动鼠标或悬停至少 10 秒，小猫桌面位置不变；按住小猫拖动后位置改变并在重启后恢复。
- 回归检查：双指按下/右键操作框和结果卡展示不受影响。

## 非目标

- 不改变动画幅度、频率或美术资源。
- 不增加新的动画开关设置。
- 不改变摘要卡的出现和隐藏延迟。
